Lock every download. Build offline in Nix.

A purifier is a plugin and a Nix library for one language build tool. The tool still plans the build. The purifier records every file the build downloads in a lockfile, and Nix builds the project from that lockfile in its sandbox.

How it works

  1. Lock

    The purifier runs the build once with an empty cache and the network on. Every file the tool fetches goes into the lockfile by URL and SHA-256, including the tool's own launcher and its plugins.

  2. Build

    Nix fetches each locked file into the store and runs the build in its sandbox, offline. The project's published artifacts become Nix packages that other flakes can depend on.

  3. Publish

    The tool's own publish step sends the artifacts Nix built, with your usual repositories and credentials. Nothing is compiled outside the sandbox.

Day-to-day work keeps the tool's own incremental compiler. With a lockfile present, resolution reads only the locked files, so interactive builds run offline too and stay in step with what Nix builds.

Projects

sbt-purifier

Available

The purifier for sbt, the Scala build tool. It covers every level of an sbt build: sbt itself, the plugins in project/, compiler bridges and the project's dependencies. Builds can depend on other builds through their flakes.

nix run github:nix-purifiers/sbt-purifier -- nixLock

Related work

The purifiers take their model from cargo (libnix), nixcloud's fork of cargo that makes Nix its build backend. In cargo (libnix), Nix compiles each crate as its own derivation. A purifier keeps the tool's own compiler and gives Nix the downloads and the release build.
